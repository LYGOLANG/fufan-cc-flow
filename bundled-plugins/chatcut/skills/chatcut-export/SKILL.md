---
name: chatcut-export
description: 当用户要导出成片、出片、渲染最终视频、或要给成片配上背景音乐时使用。按最终时间轴执行归一化、拼接、叠加标注、压制字幕与混音，产出 1080p MP4 并用 ffprobe 复核。
---

[任务]
    把当前工程渲染成一集可交付的成片，并用机器判据证明它是对的。

[启动检查]
    1. **先 `request_claim`**。用户在工作台点「导出成片」时请求进的是 `.chatcut/requests/queue.json`，
        **不会**自动变成一次 Tool 调用；不认领就动手，界面上那次点击永远等不到回音，
        请求会一直挂在 pending / claimed 直到租约到期。
        认领拿到的 requestId **原样传给后续每一个 Tool**（`export_render` 的 requestId 参数），
        写回时队列条目才自动结单。做不成就 `request_resolve`（failed）或退回（released），不许让它烂在那儿。
        认领是带租约的独占，默认 600 秒；导出是分钟级任务，就用默认值，别调短。
        队列是空的它会明说，那就照常处理用户当前的对话请求。
    2. 检查是否存在缺失素材的片段。存在就停下，让用户先重新定位——缺素材导不出完整的片子。
    3. 检查旁白是否已合成。没有配音时时间轴没有主时钟，先提示用户。
    4. 输出目录默认项目下的 renders/。要覆盖同名文件时必须先问用户。

[执行]
    调用 `export_render` 启动长任务，**带上启动检查里认领来的 requestId**，
    用 `job_status` 汇报阶段。五个阶段依次是：
    1. 归一化：每段素材统一到 1920x1080 / 30fps / yuv420p / 48kHz 立体声
    2. 拼接：把归一化后的中间件接成一条
    3. 叠加：把标注的透明层压到画面上
    4. 字幕：按设置烧录或输出独立 SRT
    5. 混音与复核：混入 BGM，并用 ffprobe 复核最终时长

    每个阶段结束都会留下机器判据。任一判据不过即中止，不产出半成品。

[增量重导]
    用户只改了一处时，只有受影响的环节会重跑，其余复用缓存。
    改一句旁白的代价与全片长度无关，只与那一段有关。不要主动全量重跑。

[失败处理]
    任一阶段失败时中间产物全部保留，修好后可以从失败的阶段续跑。
    向用户报告：失败在第几阶段、命令退出码、日志末尾几行、中间产物在哪。

[完成标准]
    - 产出 1920x1080 的 MP4，路径明确告知用户。
    - 时长以 ffprobe 实测为准并与时间轴计算值一致。渲染工具自报的时长不可信，不要引用它。
    - 各阶段的机器判据齐全，没有只凭退出码就宣告成功的环节。

[禁止]
    - 不 `request_claim` 就直接执行界面提交的导出，或调 `export_render` 时丢掉 requestId。
    - 用命令退出码 0 作为成功证据。ffmpeg 会一边产出坏文件一边返回 0。
    - 某个标注层渲染失败就静默跳过它，产出一个"少了点东西"的成片。
    - 未经确认覆盖用户已有的成片文件。
    - 把预览质量的产物当成最终交付物。
