[定位]
    采访的目的不是问得多，而是用有限问题获得足够完整、可执行、可验证的 Plugin 定义。
    适用于：
    - plugin-spec-builder。
    - plugin-interaction-runtime-design。

[采访循环]
    每轮执行：
    1. 倾听用户新信息。
    2. 抽取明确事实、推断、默认、待定和矛盾。
    3. 把零散信息放回完整用户旅程。
    4. 检查潜在连带需求。
    5. 选择当前价值最高的未知。
    6. 用用户能理解的方式问 1 个主问题，可带 1 个强相关副问题。
    7. 简短回放新理解。
    8. 检查是否已经可以收敛。

[信息分类]
    【明确】
        用户直接说过，不能擅自改写。

    【推断】
        从场景和需求邻接关系推导；必须说明推断链和风险。

    【默认】
        低风险、有可靠行业或 Harness 默认、不会改变用户控制权的决定。

    【待定】
        会改变首版范围、宿主、交互、权限、安全或验收，必须解决。

    【矛盾】
        两条需求不能同时成立；必须指出冲突场景并让用户选择。

[采访风格]
    - 采访，不是一次性问卷。
    - 每轮默认 1 个主问题，可带 1 个强相关副问题，且属于同一决策。
    - 先回放，再追问。
    - 用户已经回答的信息不重复问。
    - 不用 MCP、CSP、Host Bridge、幂等、Schema 等术语考用户。
    - 需要用户选择时给 2-3 个可感知选项、影响和推荐。
    - 只问会改变结果的问题。

[潜在连带需求]
    [文件导入]
        检查格式、数量、大小、进度、失败、项目归属、代理资源和拖拽。

    [画布、时间线、节点或直接操作]
        检查选择、多选、撤销、缩放、键盘、自动保存、冲突和删除。

    [AI 生成或修改]
        检查进行中状态、取消、重试、多版本、原始内容、参考素材、插入位置和溯源。

    [长任务]
        检查 Job ID、进度、取消、重连、重复提交、防丢失和失败日志。

    [网络与外部服务]
        检查认证、Secret、域名、离线、限流、数据离开本地和用户确认。

    [破坏性操作]
        检查确认、预览、版本、备份、撤销、幂等和权限边界。

[推断处理]
    - 低风险且有可靠默认 → 采用默认并记录，可被用户覆盖。
    - 中风险 → 给建议和影响，请用户确认。
    - 高风险、破坏性或改变架构 → 必须追问。
    - 相关但不阻断 Golden Path → 放入 Backlog，不扩张首版。

[收敛标准]
    不按“问了多少题”单独判断。
    同时检查：
    - P0 决策单元是否齐全。
    - 是否还有高风险未知。
    - 是否有未解决矛盾。
    - 是否能完整演练 Golden Path。
    - 是否能写出可测试验收。

    全部满足后：
    1. 做一次收敛回放。
    2. 区分用户确认、Harness 推断和默认。
    3. 生成产出物。
    4. 停止继续询问低价值偏好。

[提问工具边界]
    宿主提供选择题工具时（Claude Code 的 AskUserQuestion）：header 不超过 12 字符，每题 2-4 个选项，一次最多 4 题；系统自动附加 Other 自由输入，不要自建“其他”选项。
    无选择题工具的宿主（Codex）：正文列出编号选项，让用户回编号或自由作答。
    多选只用于可任意组合的项；互斥选择不开多选。

[禁止]
    - 一次发 20 个问题。
    - 把推断写成用户原话。
    - 为了显得全面无限发现新功能。
    - 让用户决定专业实现细节。
    - 没有演练 Golden Path 就宣告需求或设计齐全。
    - Gate 已通过后继续问低价值颜色、框架或实现偏好。
