---
name: design
description: 为有界面的产品定设计规范，并用出厂零件做出能在浏览器里打开的 HTML 设计稿：先做几个方向让用户选，再铺全部页面，让每条已确认需求在界面上有落点。需求文档里做什么、给谁、主流程已确认，用户想看界面长什么样、选风格、定组件规范时用。命令行工具和没有界面的产品不用。产出：设计规范.md 和 设计/ 目录里的 HTML 稿。
---

[任务]
    在写代码之前把界面定下来：先定规范——颜色、字、间距、组件长什么样；再做稿子。稿子就是 HTML 文件，放在项目根目录的 设计/ 里，用自带的浏览器工具打开给用户看，让他选、让他挑刺。目标是每条已确认需求在稿子里有一个落点。用户多半不懂设计，你给默认让他否决，不问他"你要什么风格"。

[前置]
    需求文档里至少地基几条已确认：做什么、给谁、主流程。
    自带的浏览器工具要连着；没连上先让用户连上再开始。

[先收四样]
    画之前问他要四样东西：喜欢的产品截图并说喜欢什么；讨厌的反例并说讨厌什么；已有的品牌资产——logo、颜色、字；密度偏好——一屏想看很多还是留白。他给不出，你给两三个真实产品当选项让他挑，问"像 A 还是像 B"，不问"简洁还是丰富"。
    他说的形容词——高级、简洁、活泼——翻译成能落地的东西：留白多少、颜色几种、圆角大小，翻完读给他听。

[出厂规范和零件]
    starter/ 里是出厂的变量、零件、kit 页和两份规矩，清单见 [文件结构]。先认产品是哪种终端、哪类场景，按场景规矩.md 里那一段来；有主任务区的场景（画布、剪辑、电商生图、写作、看板）各有零件包，用哪个就把它的 CSS 一起复制进 设计/，先打开对应的 kit 页看一遍再拼。
    这套是兜底，不是天花板。用户没给样板、你没有更好的想法、或者要快的时候，把 tokens.css、base.css 和用得上的零件包复制进 设计/ 拼；用户有样板就读样板的值替换进 tokens.css。你有更好的设计就做你的——条件只有一个：自己成体系，一套变量、一套零件，页面只从体系里取值，不一处一个数。

[设计规范]
    先写规范再做稿，稿子只用规范里的东西。模板在 templates/设计规范.md，写在项目根目录的 设计规范.md；值从 tokens.css 抄过来，改了哪个两边一起改。
    值从真东西里读：用户点名某个产品当样板，用自带的浏览器打开它，读计算样式——底色、文字分级、按钮、字号字重、圆角、投影——写成规范里的值，不凭印象复刻。
    深浅两套、几个断点、支持什么平台，按这个产品的需求文档定，不默认都做。

[方向]
    先做首屏，不铺开做全站。做两到四个方向，每个方向一个 HTML 文件，只变空间怎么组织，不变颜色和字，用户比较的是方向不是配色。每个方向配一句动机一句代价，不给自己偏爱的那个多说好话。
    用自带的浏览器打开给他看，让他选一个。他说"太挤""要呼吸感"，先删内容再调间距。

[做全部页面]
    方向定了，用同一套壳生成所有页面，壳的数字改一处全页同步。每页一个 HTML，或一个文件里几个页面能切换，用户打开就能看。
    样例数据全部虚构，页面上标明；多页的样例要说同一时刻、数据能对得上。
    每个主流程画起点、中间态、结果；每个要输入的动作画对话框；每个破坏性动作画确认；首日的空状态画出来。首屏之外的东西——展开、二级页、面板——也要画出来在哪，没画就等于删了需求。

[自查]
    交付前按上一段过一遍漏画清单，再按 starter/出厂设计规范.md 的反丑清单和交互清单逐条对，一条不过不交付。
    每一稿都截图看一眼再交付：用 scripts/screenshot.sh 截，自己看图——颜色是不是多了、边框是不是多了、留白是不是不对称、字是不是挤——看到了就改，改完再截。
    量像素不靠肉眼：对称位置的留白必须相等，同一行标题在同一水平线；每页量右边缘、底边、页头基线三条线，任一不齐不交付。scripts/ 里有截图和量边的脚本。overflow-check.js 在页面里跑，超框、压框、堆叠零条。
    做完把需求清单的"设计落点"填上：每条已确认需求在哪一页、哪个状态。填不上的是缺口，回去补画，不当取舍。

[完成标准]
    设计规范写好；方向用户选定；所有页面的 HTML 在 设计/ 里，他打开看过说了"可以"；每条已确认需求在需求清单上有设计落点；漏画清单过了；留白和三条线量过。
    进入开发之后，界面以产品代码和设计规范为准，稿子不再跟着改。

[文件结构]
    design/
    ├── SKILL.md
    ├── templates/设计规范.md       第一次建规范用
    ├── starter/
    │   ├── tokens.css              出厂变量，深浅两套
    │   ├── base.css                出厂基础零件，含 Agent 类零件
    │   ├── kit.html                基础零件全摆出来，每种状态都有
    │   ├── canvas.css / kit-canvas.html      画布类零件包 + 它的 kit 页
    │   ├── timeline.css / kit-timeline.html  剪辑类
    │   ├── gallery.css / kit-gallery.html    电商生图类
    │   ├── editor.css / kit-editor.html      写作类
    │   ├── charts.css / kit-charts.html      看板与图表
    │   ├── 出厂设计规范.md         原则 + 反丑清单
    │   └── 场景规矩.md             按终端、按业务场景的规矩
    └── scripts/
        ├── screenshot.sh           用本机 Chrome 无头截一页
        ├── edges.py                扫截图像素，打印两侧留白和内容边界
        └── overflow-check.js       在页面里跑，找出超框、横向溢出、被裁掉的按钮
