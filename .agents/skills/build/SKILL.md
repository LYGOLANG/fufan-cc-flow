[任务]
    按开发计划把产品做出来。一个阶段做完再做下一个；每个阶段做完，需求清单的"已实现"打勾。

[前置]
    开发计划写好。做某个阶段之前，先把它验收自的那几条需求和涉及的设计稿原文读一遍，不凭记忆。

[第 0 阶段：搭骨架和仓库]
    骨架按开发计划里第 0 阶段的定义搭。
    建仓库前用一句人话讲清 git 是什么：commit 是存档点，随时能回到那一刻；push 是把存档备份到 GitHub。讲这一次就够，以后每次提交只说一句"存了一个档"。
    本机仓库一定建，不需要账号。有 GitHub 账号就建私有仓库推上去，登录要他自己在浏览器里做；没有账号就先只在本机提交，告诉他想备份到云端时再说。仓库地址记进开发计划的约定。

[每个阶段]
    改界面前先读设计规范和组件清单，能复用的复用，不另造一套。
    没 key 的按开发计划里写的，用固定数据代替外部服务的返回，接口保留，key 到了再换成真的。
    不做假功能：每个按钮、设置项、快捷键都真的接上；做不了的功能不留能点的东西。
    同一个错修了三次还在，停下来告诉用户，不无限试。

[测试]
    测试用例的名字直接用验收条件那句 Given / When / Then，看名字就知道对应哪条。
    只写这个阶段验收要的测试，不硬凑。测试不碰用户的真数据和真凭证，用临时目录。

[阶段结束]
    跑全部测试和类型检查，看退出码，不看最后几行。
    把产品跑起来，按这个阶段的验收条件快速过一遍；完整的验证在复核时做。
    需求清单"已实现"打勾，开发计划这一行改状态。
    提交并推送——没连 GitHub 的只提交。关于 git 对用户只说一句"存了一个档，推上去了"。
    写进文档和提交说明的日期取本机当前时间，不凭记忆。

[完成标准]
    这个阶段验收自的每条 Given / When / Then 都能当场演示；测试全过；已提交；需求清单和开发计划都改了。
